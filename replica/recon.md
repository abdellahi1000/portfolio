There is no help center, pricing page, changelog, or app store listing — this

## Core loop

A visitor scrolls (or steps via "Next product") through a stack of
full-width product sections, each pitching one product with a tagline,
feature bullets, and an outbound "visit ..." link.

## Screens

It is one page, so "screens" here are the sections of that page. Each product
section shares one template (S02).

| ID | screen | route / how to reach | purpose | key components | states seen |
| --- | --- | --- | --- | --- | --- |
| S01 | Hero / header | `/` top | brand ("Scout") + tagline "We build fun products that bring people together" | logo, tagline, nav hint | default |
| S02 | Product section (x6) | scroll or "Next product" | pitch one product | large heading, 1–2 sentence description, feature list with SVG icons, outbound CTA link, product imagery | default |
| S03 | Footer | `/` bottom | recruit + close | repeated logo badges (decorative), "build with us" link | default |

The six instances of S02, in order:

1. **Crew** — "Music for top 1% fans"; connects Spotify/Apple Music, leaderboards, NFT unlocks
2. **Private Key** — "Behind-the-scenes for close friends"; shared camera roll
3. **OnScout** — "A digital room that's yours"; customizable 3D rooms, "MySpace for the Roblox generation", ~200k sign-ups stat
4. **is.online** — "Livestreaming for the rest of us"; avatar-based streaming, watch parties
5. **ideasby.ai** — "Content ideas generated by GPT-3"
6. **takeme.to** — "One home for all your links"; link-in-bio with analytics

## Flows

```
F01 Visitor browses the products
    S01 -> S02 (x6, scroll or "Next product") -> S03
    happy path clicks: 0 (pure scroll) or 6 (stepping with "Next product")
    edge: deep link to a product section (anchor), mobile layout, reduced motion

F02 Visitor exits to a product
    any S02 -> "visit <product>" outbound link (new tab)
    happy path clicks: 1

F03 Visitor applies to join
    S03 -> "build with us" outbound link
    happy path clicks: 1
```

## Inferred data model

```
Product  name, tagline, description, features[] (icon + text), cta_label,
         cta_url, image(s), optional stat (e.g. "200,000 sign-ups"),
         optional app_store_links[]
         evidence: the six identically-structured S02 sections
         confidence: high
```

Relationships: none — a flat ordered list of Products. **There is no backend
and no database**; this is static content. In a clone it is a content array
(JSON/MDX/CMS), not SQL. replica-architect should plan a static site, not an
app.

## Feature matrix

See `features.csv`. Must: 7, should: 4, could: 3, skip: 2.

## Out of scope (cannot or should not be cloned)

- The six products themselves — they are Scout's actual businesses. The clone
  showcases **your** projects in the same format.
- Scout's name, logo, copy, taglines, and product screenshots (clean-room
  rule: the template is cloneable, the content is theirs).
- The "~200,000 sign-ups" social proof — real numbers only.

## Size

Screens 3 (one repeated template), flows 3, entities 1. Hard parts: the
scroll/"Next product" section transitions and animation polish, responsive
imagery, and making a repeated template feel distinct per product. Size: **S**
— a weekend. This is the smallest possible Replica target: a static
single-page site.
